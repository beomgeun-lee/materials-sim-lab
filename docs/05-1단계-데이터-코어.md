## 확인된 사실

| 비교 | 원자량 0.1% 초과 차이 | 밀도 2% 초과 차이 |

| periodictable ↔ mendeleev | 8 / 118 | 17 / 92 |
| PubChem ↔ mendeleev | 13 / 118 | 15 / 96 |

- PubChem 일괄 CSV 는 원자량을 반올림해 둔다(Li 7.0, Ar 39.9). 조사 문서의 주의 사항과 같다.
- 배포용 원자량 정본은 periodictable, 교차검증은 PubChem 으로 둔다.

### 데이터별
- **Materials Project**
  - 받은 건수는 163,211건이다. 레지스트리에 적힌 S3 280,159건과 11.7만 건 차이가 나는데, GNoME 배치로 추정되지만 확인하지 못했다.
  - 요약 물성의 에너지 기준은 GGA/GGA+U/r²SCAN 혼합이다. 반면 A1·A2 는 GGA/GGA+U 엔트리만 쓴다. 두 기준은 `correction_scheme` 에 따로 표시되며 섞지 않는다.
  - v2026.04.13 부터 ID 가 새 형식(`mp-aaa…`)이다. 예전 ID(`mp-149`)로는 조회되지 않는다.
- **COD**
  - REST 검색에는 광물 필터가 없어 OPTIMADE 의 `_cod_mineral IS KNOWN` 필터로 받았다. 162번 요청, 요청 간격 1초, 12.9분, 13.3 MB가 들었다.
  - 광물 항목에는 R 값이 사실상 비어 있다. 그래서 대표 구조는 화학식 일치와 최빈 공간군으로 고른다. 이 기준으로 'Spinel' 이름으로 올라 있던 고압상(Pbnm)을 걸렀다.
- **IMA:** 산화수 위첨자와 두 줄짜리 화학식 때문에 `pdftotext -tsv`(낱말 좌표)로 복원했다.
  - 치환식 `(Mg,Fe)` 는 억지로 첫 원소로 읽지 않는다. 예를 들어 augite 를 첫 원소로 읽으면 CaSiO₃ 가 되어 규회석으로 오해된다.
  - 이 때문에 파싱하지 못한 광물이 801종이다.
- **USGS MCS:** ScienceBase 가 Cloudflare 봇 검사로 스크립트 다운로드를 막는다.
  - 이번에는 에이전트가 브라우저 자동화로 받았고, 파일은 공개 MD5 와 일치한다.
  - 봇 검사를 우회하는 방식이므로, 새 판은 **사용자가 브라우저로 직접 받아** `data/raw/usgs-mcs/<판>/` 에 두는 것으로 한다 (`fetch()` 가 URL 을 안내한다).
- **mendeleev 1.3.0:** 조회 함수가 pandas 3 와 호환되지 않는다. 그래서 패키지에 든 SQLite 를 직접 읽는다.
- **CAMEO:** CID 하나에 데이터시트가 여러 개 연결된 경우가 있다(무수 염화수소·염산). 이럴 때 그룹은 합집합으로 쓴다.

### 해석기
- 광물명은 IMA 정본명과 대표 COD 구조로 해석한다(예: `mineral:calcite` → `IMA 2026-09 · COD 9014216`). PubChem 으로 광물을 찾으면 수화물이나 이온 형태 화학식이 오는 경우가 많았다(예: 실리마나이트 → Al₂SiH₆O₅).
- 한글 이름과 `ke:` 참조는 KOSHA 목록에서 CAS 를 찾은 뒤 PubChem 으로 넘긴다.
  - **정확히 같은 이름일 때만** 채택한다. 예를 들어 "표백제"를 부분 일치로 받으면 코닥 현상액이 걸리기 때문이다.
  - 이 경로에는 data.go.kr 키가 필요하다.
- 수화물 표기 `CuSO4·5H2O` 를 읽는다.
- 남은 실패 2건:
  - `iron(III) oxide`: PubChem 이름 조회가 이 표기를 찾지 못한다.
  - `메탄올`: KOSHA 에는 다른 국문명으로 올라 있다.
- S0 의 반응성 그룹은 적재된 로컬 CAMEO 테이블을 먼저 본다(오프라인 동작).
