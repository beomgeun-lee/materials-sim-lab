## 1. 웹 화면 (작업대)

```bash
uv run msl serve          # → http://127.0.0.1:8000
```

| 주소 | 하는 일 |
|---|---|
| `/` | **작업대** — 레시피를 만들고 고치고 [실행]·[저장]. 결과 카드가 오른쪽에 나온다 |
| `/spaces` | 조합 공간 목록 + **편집기** — 틀에서 시작하거나 기존 공간을 고쳐 [확인]·[실행]·[저장] |

**작업대에서 레시피 만들기**
1. 위쪽 카드에서 예제를 고르거나 **+ 새 레시피**를 누른다.
2. 성분을 넣는다.
   - 입력칸에 이름·CAS·화학식·광물명을 적고 [추가] — 예: `염산`, `가성소다`, `7647-01-0`, `Fe2O3`, `hematite`, `sodium chloride`
   - 또는 **시약 선반** 버튼(물·염산·철·방해석 등 21종)을 누른다.
   - 흔한 국문 관용명(염산·가성소다·락스·초산·베이킹소다·생석회 등 33종, `kb/aliases_ko.yaml`)은 정식 이름 없이도 찾는다.
3. 각 성분의 양·단위·상태를 고치고, 필요 없으면 ✕ 로 뺀다.
4. 조건(온도·압력·분위기·pH·전위 Eh·모드)을 정한다. 고급에서 스윕과 메모를 넣을 수 있다.
5. 시험은 **자동 선택**(성분에 맞춰 고름) 또는 **직접 고르기**. 아래 '실행하면 고르는 시험'이 바로 바뀐다.
6. [실행] → 오른쪽에 결과. [저장] → `recipes/{id}.yaml` 로 저장되고 위쪽 '내 레시피'에 나온다.
   - 같은 id 가 있으면 [덮어쓰기]를 한 번 더 눌러야 한다. 예제는 고치지 않는다(같은 id 로 저장 불가 → id 를 바꿔 저장).
7. 'YAML — 직접 고치기'를 열면 레시피 파일을 직접 고치고 [YAML 적용]으로 작업대에 반영할 수 있다.

잘못 적은 곳은 빨간 상자에 한국어로 나온다 (예: `성분 · 1번째 · 양: 성분 양은 0보다 커야 함`).

**조합 공간 편집기** — `/spaces` 아래쪽
- [혼합비 격자]·[양 스윕]·[조합 열거] 틀에서 시작하거나, 목록의 [편집기로]로 기존 공간을 불러온다.
- [확인]은 만들 레시피 목록을, [실행]은 결과 표·곡선을 보여 준다. [저장] → `spaces/{id}.yaml`, '내 조합 공간'에 나온다.

## 2. 레시피 실행 (터미널)

```bash
uv run msl run examples/recipes/iron-water.yaml                     # 결과를 터미널에
uv run msl run examples/recipes/iron-water.yaml --report 결과.html   # 리포트 파일 (.md 도 가능)
uv run msl run examples/recipes/iron-water.yaml --json 결과.json     # 원자료
uv run msl run examples/recipes/iron-water.yaml --no-cache          # 캐시 없이 다시 계산
```

## 3. 레시피 직접 쓰기

```yaml
id: rcp-my-test            # rcp- 로 시작, 영소문자·숫자·하이픈
name: 구리 + 묽은 염산
components:
  - ref: element:Cu
    amount: 5 g
    state: solid            # solid · liquid · gas · aqueous
  - ref: cas:7647-01-0      # 염화수소
    amount: 0.1 mol
    state: aqueous
  - ref: cas:7732-18-5      # 물
    amount: 1 L
    state: liquid
conditions:
  T: 25 °C
  atmosphere: air           # 선택: pH, Eh(전극 전위 V vs SHE), P, time
assays: auto                # 자동 선택. 직접 고르려면 [S0, A4, A5]
```

| 항목 | 쓸 수 있는 것 |
|---|---|
| 성분 참조 | `element:Fe` · `formula:Fe2O3` · `mineral:hematite` · `cas:7647-01-0` · `cid:313` · `name:표백제` · `ke:KE-20189` · `mp:mp-19770` · `cod:9000660` · `material:epoxy-generic` |
| 양 | g · kg · mg · mol · mmol · L · mL · mol/L(M) · mol/kg · wt% · at% · mol% · vol% |
| 모드 | 기본은 혼합물. `mode: system` 이면 원소계 탐색 (양 없이 원소만) |
| 스윕 | `sweep: {param: T, start: 300 K, stop: 1800 K, steps: 31}` (T·P·ratio) |

형식 확인: `uv run msl recipe check 파일.yaml`

## 4. 조합 공간 (여러 조합을 한 번에)

```bash
uv run msl space expand examples/spaces/cu-ni-composition.yaml    # 만들 레시피 목록만
uv run msl space run examples/spaces/cu-ni-composition.yaml --report 결과.html --csv 결과.csv
```

| 예제 (`examples/spaces/`) | 생성 방식 | 결과 |
|---|---|---|
| `cu-ni-composition` | ratio (혼합비 격자) | 조성별 고상선·액상선 곡선 |
| `hcl-naoh-titration` | amount (양 스윕) | 적정 곡선 |
| `reagent-shelf-s0` | subsets 2개씩 | 시약 7종 혼합 위험 행렬 |
| `metals-in-water` | subsets 1개씩 + 물 | 금속 8종 부식 판정 |
| `li-tm-oxides` | subsets 원소계 | Li–전이금속–O 계 비교 |

공간 정의는 세 부분이다.

```yaml
id: spc-my-space
name: 내 공간
base:                       # 레시피 틀: 고정 성분·조건·시험
  components: [{ref: "cas:7732-18-5", amount: 1 L, state: liquid}]
  conditions: {pH: 7, atmosphere: air}
  assays: [A5]
generator:                  # 무엇을 바꿀지 — ratio / amount / subsets
  kind: subsets
  size: 1
  pool: [{ref: "element:Fe", amount: 1 g, state: solid}, {ref: "element:Zn", amount: 1 g, state: solid}]
collect:                    # 결과 표의 열 — value(값 이름·앞부분, unit) 또는 field(verdict·summary·status)
  - {assay: A5, field: verdict, label: 판정}
```

같은 `chart:` 이름을 준 열은 한 차트에 겹쳐 그린다 (예: 고상선·액상선).

## 5. 점검·데이터 관리

```bash
uv run msl validate                 # 검증 세트 40개 채점 (S0 재현율 100%, 나머지 90% 기준)
uv run msl resolve-check            # 해석기 시험 목록 200개 (기준 95%)
uv run msl bench phreeqc --dist <배포본> --binary <phreeqc>   # PHREEQC 공식 예제 재현
uv run msl db status                # 적재 현황
uv run msl db fetch <소스|all>       # 원본 스냅샷 받기 (data/raw, SHA256SUMS)
uv run msl db load <소스|all>        # 정규화해 적재 (data/open · data/restricted)
uv run msl registry check           # 소스·엔진·라이선스 레지스트리 검사
uv run pytest                       # 테스트
```

## 알아 둘 점

- `.env` 에 `MP_API_KEY`(A1·A2·A5·A7)와 `DATA_GO_KR_SERVICE_KEY`(A10, 국문명 해석)가 있어야 한다. 없으면 해당 시험은 '대기'로 표시된다.
- 같은 레시피는 결과 캐시에서 바로 읽는다. 코드·데이터·엔진 판이 바뀌면 자동으로 다시 계산한다.
- A6 합금은 TDB 라이선스 미확인이라 연구용이다 ([D14](03-결정-기록.md)).
- S0 '규칙 해당 없음'은 자체 규칙 10개에 없다는 뜻이며 안전하다는 뜻이 아니다.
- 결과 카드의 '한계' 줄은 그 시험이 모르는 것(속도, 온도 범위, 근사 오차 등)을 적는다. 판단 전에 확인할 것.
