## 1. 웹 화면 (작업대)

```bash
uv run msl serve          # → http://127.0.0.1:8000
```

| 주소 | 하는 일 |
|---|---|
| `/` | **작업대** — 레시피를 만들고 고치고 [실행]·[저장]. 결과 카드가 오른쪽에 나온다 |
| `/spaces` | 조합 공간 목록 + **편집기** — 틀에서 시작하거나 기존 공간을 고쳐 [확인]·[실행]·[저장] |
| `/predict` | **물성 예측** — 화학식을 넣으면 L1 대리모델이 형성에너지·안정성·밴드갭·밀도를 추정 (아래 5절) |
| `/recommend` | **목표 기반 추천** — 원소와 조건을 주면 조성 후보를 만들어 평가·순위 (아래 6절) |

**작업대에서 레시피 만들기**
1. 위쪽 카드에서 예제를 고르거나 **+ 새 레시피**를 누른다.
2. 성분을 넣는다.
   - 입력칸에 이름·CAS·화학식·광물명을 적고 [추가] — 예: `염산`, `가성소다`, `7647-01-0`, `Fe2O3`, `hematite`, `sodium chloride`
   - 또는 **시약 선반** 버튼(물·염산·철·방해석 등 21종)을 누른다.
   - 흔한 국문 관용명(염산·가성소다·락스·초산·베이킹소다·생석회 등 33종, `kb/aliases_ko.yaml`)은 정식 이름 없이도 찾는다.
3. 각 성분의 양·단위·상태를 고치고, 필요 없으면 ✕ 로 뺀다.
4. 조건(온도·압력·분위기·pH·전위 Eh·모드)을 정한다. 고급에서 스윕과 메모를 넣을 수 있다.
5. 시험은 **자동 선택**(성분에 맞춰 고름) 또는 **직접 고르기**. 아래 '실행하면 고르는 시험'이 바로 바뀐다.
6. [실행] → 오른쪽에 결과. [저장] → `recipes/{id}.yaml` 로 저장되고 위쪽 '내 레시피'에 나온다.
   - 같은 id 가 있으면 [덮어쓰기]를 한 번 더 눌러야 한다. 예제는 고치지 않는다(같은 id 로 저장 불가 → id 를 바꿔 저장).
7. 'YAML — 직접 고치기'를 열면 레시피 파일을 직접 고치고 [YAML 적용]으로 작업대에 반영할 수 있다.

잘못 적은 곳은 빨간 상자에 한국어로 나온다 (예: `성분 · 1번째 · 양: 성분 양은 0보다 커야 함`).

**조합 공간 편집기** — `/spaces` 아래쪽
- [혼합비 격자]·[양 스윕]·[조합 열거] 틀에서 시작하거나, 목록의 [편집기로]로 기존 공간을 불러온다.
- [확인]은 만들 레시피 목록을, [실행]은 결과 표·곡선을 보여 준다. [저장] → `spaces/{id}.yaml`, '내 조합 공간'에 나온다.

## 3. 레시피 직접 쓰기

```yaml
id: rcp-my-test            # rcp- 로 시작, 영소문자·숫자·하이픈
name: 구리 + 묽은 염산
components:
  - ref: element:Cu
    amount: 5 g
    state: solid            # solid · liquid · gas · aqueous
  - ref: cas:7647-01-0      # 염화수소
    amount: 0.1 mol
    state: aqueous
  - ref: cas:7732-18-5      # 물
    amount: 1 L
    state: liquid
conditions:
  T: 25 °C
  atmosphere: air           # 선택: pH, Eh(전극 전위 V vs SHE), P, time
assays: auto                # 자동 선택. 직접 고르려면 [S0, A4, A5]
```

| 항목 | 쓸 수 있는 것 |
|---|---|
| 성분 참조 | `element:Fe` · `formula:Fe2O3` · `mineral:hematite` · `cas:7647-01-0` · `cid:313` · `name:표백제` · `ke:KE-20189` · `mp:mp-19770` · `cod:9000660` · `material:epoxy-generic` |
| 양 | g · kg · mg · mol · mmol · L · mL · mol/L(M) · mol/kg · wt% · at% · mol% · vol% |
| 모드 | 기본은 혼합물. `mode: system` 이면 원소계 탐색 (양 없이 원소만) |
| 스윕 | `sweep: {param: T, start: 300 K, stop: 1800 K, steps: 31}` (T·P·ratio) |

형식 확인: `uv run msl recipe check 파일.yaml`

|---|---|---|

공간 정의는 세 부분이다.

```yaml
id: spc-my-space
name: 내 공간
base:                       # 레시피 틀: 고정 성분·조건·시험
  components: [{ref: "cas:7732-18-5", amount: 1 L, state: liquid}]
  conditions: {pH: 7, atmosphere: air}
  assays: [A5]
generator:                  # 무엇을 바꿀지 — ratio / amount / subsets
  kind: subsets
  size: 1
  pool: [{ref: "element:Fe", amount: 1 g, state: solid}, {ref: "element:Zn", amount: 1 g, state: solid}]
collect:                    # 결과 표의 열 — value(값 이름·앞부분, unit) 또는 field(verdict·summary·status)
  - {assay: A5, field: verdict, label: 판정}
```

같은 `chart:` 이름을 준 열은 한 차트에 겹쳐 그린다 (예: 고상선·액상선).

## 5. 물성 예측 (L1 조성 모델)

DB 에 없는 새 조성을 빠르게 걸러 볼 때 쓴다. 화학식만 보고 몇 초 안에 추정한다.

```bash
uv run msl ml train                                   # 처음 한 번 — MP 조성 97,666개로 학습 (약 15분, data/models/)
uv run msl predict Li1.2Ni0.6Mn0.2O2 LiFePO4 CsPbI3   # 터미널 예측
```

웹: `/predict` 에서 한 줄에 하나씩 화학식(또는 이름)을 넣고 [예측].

| 나오는 값 | 뜻 |
|---|---|
| 형성에너지 (80% 구간) | 원소로부터 만들 때의 에너지(eV/atom). 음수일수록 잘 생긴다. 구간은 실제 값이 80% 확률로 들어올 범위 |
| hull 거리 · 판정 | 알려진 다른 상들보다 얼마나 불안정한가. ≤ 0 안정 예측 · 0~0.05 준안정 · 그 이상 불안정 (분해 생성물 표시) |
| 밴드갭 · 금속일 확률 | PBE 기준 (실측보다 약 40% 작게 나오는 경향을 그대로 배움) |
| 밀도 | 예측한 원자당 부피에서 계산 |
| 비슷한 알려진 물질 | 특성이 가장 가까운 MP 물질 3개와 그 DFT 값 — 예측의 근거를 가늠 |
| DB 에 있음 / 학습 범위 밖 | DB 에 있으면 DFT 값을 쓰라고 안내, 학습 데이터와 너무 다르면 '신뢰 낮음' |

레시피에서도 쓰인다: 작업대·`msl run` 에서 MP 에 없는 조성(예: `formula:Li1.2Ni0.6Mn0.2O2`)이 성분이면
A1(안정성)·A7(물성)이 L1 예측값을 붙이고 결과 카드에 **L1** 배지와 모델 판을 표시한다.

**정확도** (학습에 쓰지 않은 시험 조성 기준 · 학습에 없던 원소 조합에서도 거의 같음)
- 형성에너지 평균 오차 0.07 eV/atom, 80% 구간은 실제로 79% 를 덮는다
- 밴드갭 평균 오차 0.41 eV, 금속/비금속 판별 90%, 원자 부피 평균 오차 0.8 Å³
- **안정성 판정은 73% 만 맞는다** — 예: 실제로 안정한 초전도체 MgB₂ 를 '불안정'으로 예측

**한계** 조성만 보므로 다형(방해석/아라고나이트)을 구분하지 못하고, 안정/불안정 경계 부근에서 자주 틀린다(Bartel 2020).
후보를 거르는 용도로 쓰고, 확인은 DFT·uMLIP(4단계 L2)·실험으로 한다.

## 6. 목표 기반 추천

원소와 원하는 조건을 주면, 만들 수 있는 조성을 모두 나열해 평가하고 순위를 매긴다.

```bash
uv run msl recommend examples/goals/sulfide-absorber.yaml --csv 후보.csv
```

웹: `/recommend` — 예제 버튼(양극재·태양전지 흡수층·경량 합금)으로 채운 뒤 고쳐서 [추천].

| 입력 | 뜻 |
|---|---|
| 필수 원소 / 선택 원소 | 모든 후보에 들어갈 원소 / 들어갈 수도 있는 원소 |
| 원소 수 최대 · 화학식당 원자 수 최대 | 후보 범위 (원자 수 10 이면 LiMn2O4 는 되고 Li4Mn5O12 는 안 됨) |
| 전하 균형 가능한 조성만 | 산화수 합이 0 이 될 수 없는 조성 제외 (혼합 원자가 허용, 금속끼리는 검사 안 함) |
| 조건 | hull 거리 · 밴드갭 · 밀도 · 형성에너지 · 금속일 확률의 최소/최대 |
| 정렬 | 낮은 순 · 높은 순 · 목표값에 가까운 순 |

결과
- **판정**: 조건을 80% 구간까지 만족하면 '충족', 구간이 경계에 걸치면 '가능성 있음'
- **출처**: DB 에 있는 조성은 DFT 값(파란 표시), 없는 조성은 L1 예측
- **주의 표시**: 학습 범위 밖이거나 알려진 hull 보다 0.1 eV/atom 넘게 낮게 예측(과대평가 의심)
- 산점도(안정성–밴드갭), 순위 표, [상세]는 물성 예측 화면으로, CSV 내려받기, 지난 실행 목록 (`data/recommendations/`)

목표 파일 형식은 `examples/goals/*.yaml` 을 참고한다.

## 7. L2 안정성 확인 (uMLIP 구조 계산)

추천·예측에서 나온 유망 조성을 실제 결정 구조로 이완해 L1 보다 정확하게 확인한다 (4단계, D19).

```bash
uv sync --extra l2                     # 처음 한 번 — PyTorch·MACE·ORB (약 1~2 GB)
uv run msl bench umlip                 # (선택) 이 컴퓨터의 처리량 실측 — 대표 구조 20개
uv run msl l2 Li6MnNi3O10              # 조성 하나의 L2 hull 거리 (두 모델)
```

하는 일
1. 그 원소계의 경쟁 상(MP 에서 hull 0.05 eV/atom 이내)을 같은 uMLIP 로 다시 이완해 hull 을 만든다 (**자기일관 hull**).
   현재 MP 에너지와 바로 비교하면 전이금속 산화물에서 0.05~0.19 eV/atom 어긋나기 때문이다 (MP v2026 의 LASPH 재계산).
2. DB 에 없는 조성은 후보 구조를 만든다 (D20).
   - 같은 원소계의 비슷한 구조(음이온:양이온 비가 같은 산화물 등)의 양이온 자리 배치 — 정전기(Ewald) 에너지가 낮은 순 + 무작위 몇 개
   - 다른 화학계에서 같은 조성 패턴(예: AB₂O₄ 스피넬)의 안정 구조에 원소를 바꿔 끼운 **구조 원형**
   - 빠른 ORB 로 모두 이완해 거르고, 상위 3개를 두 모델로 최종 계산한다.
3. MACE-MPA-0 과 ORB v3 두 모델로 따로 계산해 평균과 차이(불확실성)를 낸다.

웹: 물성 예측 카드와 추천 결과 표의 **[L2 확인]**(추천 표는 [L2]) — 서버에서 백그라운드로 돌며 진행 상황을 보여 주고,
끝나면 'L2 안정/준안정/불안정 · hull 거리 · 두 모델 차이 · 분해 생성물'을 붙인다. 계산한 결과는 저장해 두고 다음에 바로 보여 준다
(`data/cache/umlip/results/`). 작업은 한 번에 하나씩 차례로 돈다.

걸리는 시간: 새 원소계는 경쟁 상 이완에 모델마다 몇 분(Li–Mn–Ni–O 100개: MACE 4분, ORB 1.5분),
그 뒤로는 캐시(`data/cache/umlip/`)를 써서 후보 구조만 계산한다.

정확도 점검 — **재발견 시험** (`uv run msl bench l2`): DB 물질 7종(스피넬·층상·감람석·페로브스카이트 등)을 모른다고 치고
구조를 만들면 7/7 이 DB 구조와 0.01 eV/atom 이내로 같아진다 (무작위 배치만 쓰던 이전 방식은 2/7).

예: `Li1.2Ni0.6Mn0.2O2`(= Li6MnNi3O10) — L1 은 '안정(−0.063)', L2 는 **+0.040 eV/atom(준안정, 두 모델 차이 0.006)**,
최저 구조 C2/m(실제 Li-rich 층상 양극재와 같은 공간군), 분해되면 LiNiO₂ + Li₂MnO₃ + Li₂NiO₃.
합성은 되지만 Li₂MnO₃·LiMO₂ 영역으로 나뉘려는 준안정 물질이라는 실험 사실과 맞다.

결과에는 최저 구조의 **포논 안정성**(허수 모드 여부, MACE)과 **L3(DFT) 승격 판정**(권장·선택·불필요와 이유)이 붙는다.
물성 검증: `uv run msl bench props` — 탄성률(MP DFT 대비 체적 오차 4~6%)과 포논 안정성.

**한계** 배치는 Ewald 순위 상위와 무작위 표본이라 전역 최저 구조를 보장하지 않는다. 구조 원형은 조성 패턴이 정확히 같은 것만 찾는다.

## 7-1. 다음에 잴 조성 (베이지안 최적화)

L2·DFT·실험처럼 한 번 재는 데 비용이 큰 단계에서, 지금까지 잰 값을 보고 다음 조성을 고른다.

```bash
uv sync --extra bo                                            # 처음 한 번 — BayBE (torch 포함)
uv run msl suggest next examples/campaigns/li-mn-o-cathode.yaml          # 다음 후보 5개
uv run msl l2 Li3Mn2CoO4                                      # 그중 하나를 L2 로 재고
uv run msl suggest import-l2 examples/campaigns/li-mn-o-cathode.yaml Li3Mn2CoO4   # L2 값을 측정값으로
uv run msl suggest add examples/campaigns/li-mn-o-cathode.yaml LiMnO2 0.012 --source 실험 --note "XRD 단일상"
uv run msl suggest show examples/campaigns/li-mn-o-cathode.yaml          # 측정값 목록
```

- 캠페인 파일: `id`(camp-…), `goal`(목표 id) 또는 `formulas`, `pool`, `target`(prop·direction), `batch`.
- 처음에는 서로 다른 조성을 고르게 고르고, 측정값이 쌓이면 '대리모델 평균 ± 표준편차'가 함께 나온다.
- 출처(L2·DFT·실험)를 섞으면 경고가 나온다 — 한 캠페인에는 한 가지 출처를 쓰는 것이 좋다.
- 측정값은 `data/campaigns/{id}.csv` 에 쌓인다.

## 9. MCP 서버 (다른 AI 도구에서 쓰기)

Claude Code 에 등록 (한 번):

```bash
claude mcp add msl -- uv --directory <materials-sim-lab 폴더의 절대 경로> run msl mcp
```

그다음 대화에서 "염산 0.1 mol 과 물 1 L 섞으면 pH 는?" 처럼 물으면 AI 가 도구를 골라 쓴다.
Claude Desktop 은 설정 파일 `mcpServers` 에 `{"command": "uv", "args": ["--directory", "<폴더>", "run", "msl", "mcp"]}`.

| 도구 | 하는 일 |
|---|---|
| search_substance | 이름·CAS·화학식·광물명 → 참조·화학식 |
| list_recipes · get_recipe | 예제·내 레시피 목록과 YAML |
| check_recipe | 레시피 검증 (실행 안 함) + 고를 시험 |
| run_recipe | 실행 → 리포트(Markdown/JSON), `data/reports/` 에 저장 |
| list_reports · get_report | 저장된 리포트 다시 보기 |
| save_recipe | `recipes/` 에 저장 (예제 id 거부, 덮어쓰기는 명시) |
| predict_properties | L1 예측 |
| recommend | 목표 기반 추천 |
| l2_result | 저장된 L2 결과 조회 (새 L2 계산은 웹·`msl l2`) |
| list_campaigns · suggest_next · add_measurement | 캠페인 목록, 다음에 잴 조성 제안, 측정값 추가 |
| list_assays | 시험 11종 설명 |

AI 에게 줄 사용 규칙(안전 경고 먼저, 충실도·주의 사항 전달 등)은 `skills/materials-sim-lab/SKILL.md`.
