## A5 — Pourbaix (수계 안정성·부식)

**판정 방식**
- 대상: 금속(1~3종) + O·H 로만 된 고체 성분이 물·수용액과 함께 있을 때 (라우터가 자동 선택)
- pH: 레시피 조건 → A4 계산값 → 물·용액 성분만으로 PHREEQC 계산 → 7(중성 가정) 순
- 전위: 레시피 Eh → 분위기(공기 = O₂/H₂O 선 pO₂ 0.21, 불활성 = H₂/H₂O 선) → 지정이 없으면 두 극단을 모두 본다
- 판정: 성분이 그 조건에서 Pourbaix hull 위(ΔG_pbx ≤ 1 meV/atom)면 면역·안정, 아니면 안정한 화학종이 고체면 부동태, 이온이면 부식
- 금속 이온 농도 10⁻⁶ mol/kg, 25 °C (Pourbaix 도감의 관례)

**에너지 — 실험값 우선 하이브리드** (A2 v1 과 같은 앵커 원리)

| 화학종 | 에너지 출처 |
|---|---|
| 고체 (실험값 있음) | NASA 298.15 K ΔGf → 이온 데이터의 기준 고체 ΔGf (NBS) |
| 고체 (MP 에만 있음) | 실험 앵커로의 분해 반응에너지만 MP 에서 가져옴. **실험 관측 구조(ICSD)가 있는 상만** |
| 이온 | 실험 ΔGf 그대로 (기준 고체가 실험값이라 Persson 보정 항 = 0) |

**MP 원본(mp-api 기본)과 비교**

면역 상한 전위 (pH 0, 10⁻⁶ M) — 기준: 표준전위 E° + (0.05916/n)·log10(10⁻⁶)

| 금속 | 기준 | MP 원본 | 하이브리드 |
|---|---|---|---|
| Cu | +0.164 | −0.015 | +0.163 |
| Ag | +0.445 | +0.176 | +0.444 |
| Au | +1.380 | +1.004 | +1.361 |
| Pb | −0.304 | −0.819 | −0.303 |
| Sn | −0.315 | −0.479 | −0.313 |
| Fe | −0.624 | −0.561 | −0.586 |
| Ni | −0.434 | −0.380 | −0.417 |
| Zn | −0.939 | −0.910 | −0.939 |
| Al | −1.780 | −1.759 | −1.795 |
| Co | −0.457 | −0.393 | −0.459 |
| Cd | −0.580 | −0.599 | −0.578 |
| **MAE** | | **159 mV** (최대 515) | **9 mV** (최대 38) |

- Mg 는 25 °C 에서 MgH₂ 가 Mg 보다 안정해 물속 '면역' 영역이 열역학적으로 없다 → 비교에서 뺐다.
- 하이브리드의 남은 오차는 이온 데이터(NBS)와 표준전위표(CRC)의 차이다. Fe 는 Fe²⁺ ΔGf 가 두 표에서 다르다.

검증 사례 11개: 하이브리드 11/11, MP 원본 9/11.
- MP 원본은 공기 중 물에서 금이 녹는다(H₃AuO₃)고 판정한다.
- MP 원본은 Mg(OH)₂ 부동태를 놓친다. MP 수계 보정에서 수산화물이 실험보다 0.5~0.7 eV/atom 불안정하게 나온다.

**실재하는 상만 쓰는 이유** 앵커 보정만으로는 GGA 가 과안정화한 가상의 Cu₂O₃ 가 산소 선 아래에 남았다
(도감에서는 약 0.4 V 위). MP `theoretical=false` 인 상만 두자 Cu 는 Cu·Cu₂O·CuO, Fe 는 Fe·Fe₃O₄·Fe₂O₃·Fe(OH)₂ 로
도감과 같은 구성이 됐다. 지금 흔한 금속 8종 도표의 안정 고체는 AgO 하나만 MP 에 기대고 나머지는 모두 실험값이다.

**금속 8종 × 중성 물(공기 포화)** — `examples/spaces/metals-in-water.yaml`

| Au | Ag | Cu | Ni | Fe | Zn | Al | Mg |
|---|---|---|---|---|---|---|---|
| 면역 | 부식 Ag⁺ | 부동태 CuO | 부식 Ni²⁺ | 부동태 Fe₂O₃ | 부식 Zn²⁺ | 부동태 Al(OH)₃ | 부식 Mg²⁺ |

'공기 포화'는 O₂/H₂O 평형 전위(이론 상한)라서 Ag·Cu 도 면역이 아니다. 실제 자연수의 전위는 보통 이보다 0.3~0.6 V 낮고,
은은 산소 환원이 느려 실제로는 거의 녹지 않는다. 결과 카드의 한계 문구에 이 점을 적는다.

**한계**
- 평형 열역학만 본다. '부동태'는 산화물이 안정하다는 뜻이고 막이 보호성인지는 모른다(철의 녹).
- 25 °C 만 계산한다. 착화제(Cl⁻·NH₃)와 반응 속도(과전압)는 반영하지 않는다. 염화물이 있으면 경고한다.
- 다원소(최대 3종)는 성분 조성비로 고정한 도표를 그린다. 서로 다른 금속 사이의 갈바닉 부식은 보지 않는다.

## 조합 공간 생성기

레시피 틀 하나에서 여러 레시피를 만들어 돌리고, 지정한 값을 한 표로 모은다. 생성된 레시피는 보통 레시피와 같이 실행되고
결과 캐시도 재사용한다. 그래서 새 시험을 붙이면 따로 구현하지 않아도 공간 탐색이 된다.

| 생성기 | 하는 일 | 예제 | 결과 |
|---|---|---|---|
| ratio | 2~4 성분 혼합비 단체 격자 | Cu–Ni 조성 스윕 (9점) | 렌즈형 고상선·액상선. Cu50Ni50 1,262 / 1,312 °C |
| amount | 한 성분의 양 스윕 | 염산 0.1 mol + NaOH 0→0.2 mol (21점) | 당량점에서 pH 2.08 → 6.98 → 11.87 급변 |
| subsets | 풀에서 k개 조합 | 시약 선반 7종 × 2 (21쌍) | S0 쌍별 행렬: 부적합 5쌍, 주의 1쌍 |
| subsets | 1개씩 + 공통 성분 | 금속 8종 × 물 | 위 A5 표 |
| subsets | 원소계 (system 모드) | Li–M–O (M = Co·Ni·Mn·Fe) | 안정 화합물 11·8·13·8개, 준안정 후보 33·52·60·24개 |

- 결과: 터미널 표, CSV, Markdown, HTML(웹 화면과 같은 스타일, 서버 없이 열림). 1차원 공간은 곡선, 두 개씩 조합은 쌍별 행렬.
- 수집 열은 값 이름(앞부분 일치 + 단위)이나 결과 필드(verdict·summary·status)를 가리킨다. 같은 `chart` 이름끼리 한 차트에 겹친다.
- 웹: `http://127.0.0.1:8000/spaces` 에서 예제를 고르면 계산하고 표·곡선을 보여 준다.

## PHREEQC 공식 예제 재현

USGS PHREEQC 3.8.6 배포본(퍼블릭 도메인)에는 기대 출력이 들어 있지 않다. 그래서 같은 배포본 소스로 공식 `phreeqc`
실행 파일을 빌드하고, 31개 예제를 **공식 실행 파일**과 **A4 경로(phreeqpython 의 IPhreeqc)**로 같은 데이터베이스에서 돌려 비교했다.

| 비교 대상 | 결과 |
|---|---|
| 용액 기술 (pH·pe·이온 세기) | 비교 가능한 예제 모두 차이 0 (예제 22 는 147개 용액) |
| 포화지수 표 | 모두 차이 0 |
| SELECTED_OUTPUT 파일 | 최대 상대차 10⁻¹² (ex10 6,200개 값 등) |
| 판정 | **28/28 재현**. ex2b·ex19·ex19b 는 그래프(USER_GRAPH) 전용이라 비교 불가 |

- 데이터베이스: phreeqc.dat 예제는 A4 가 실제로 쓰는 phreeqpython 동봉 판(2024-05-22)으로, ex15·ex17·ex20 은 배포본의 ex15.dat·pitzer.dat·iso.dat 로 돌렸다.
- 동봉 판과 3.8.6 판 phreeqc.dat 의 차이(참고): 광물 SI 최대 0.35·pH 최대 0.165 (ex14). 예제 1 해수는 이온 세기 0.6747 대 0.6704.
- 기준값은 `kb/validation/phreeqc_examples_3.8.6.json`, 빠른 예제 5개(ex1·3·4·5·9)의 입력은 `tests/fixtures/phreeqc/`(원본 그대로, NOTICE 동봉).
  테스트는 실행 파일 없이 이 기준값과 비교한다.

**재현 작업 중 찾은 문제** phreeqpython 은 데이터베이스를 지정하지 않으면 phreeqc.dat 가 아니라 **vitens.dat**
(델프트 공대 Stimela 용으로 2015년 phreeqc.dat 를 고친 파일)을 싣는다. A4 는 2단계까지 출처를 phreeqc.dat 로 적으면서
실제로는 vitens.dat 로 계산했다. phreeqc.dat 를 명시해 싣도록 고쳤다. 검증 사례 결과는 소수 둘째 자리까지 같았다.
