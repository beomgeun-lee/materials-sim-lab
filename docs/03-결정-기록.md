# 03 · 결정 기록

확정된 결정과 근거, 그로부터 나오는 제약을 적는다. 결정을 뒤집으려면 이 문서를 먼저 고치고
[계획서](02-계획서.md)의 영향 범위를 확인한다.

2026-09-26, 계획서 11절 권고안을 그대로 채택했다. D1~D7은 11절 항목 1~7에 대응하고,
D8~D14는 0단계 착수 이후에 정했다.

---

## D1 — 1차 사용자: 연구용 SDK + MCP 코어, 교육용 첫 화면

**결정** 코어는 연구자용 Python SDK와 MCP 서버로 만든다. 사용자가 처음 보게 될 웹 화면은
교육용 가상 조합 실험실로 한다. 산업용 스크리닝은 이 두 가지를 검증한 뒤 다시 판단한다.

**파생**
- 1~4단계 산출물은 CLI와 SDK를 기준으로 한다. 웹 UI는 5단계에서 시작한다.
- 교육용 화면을 전제로 하므로 3.5절 표현 규칙(조건 배지, 한계 문구)은 선택이 아니라 필수다.

## D2 — 라이선스 정책: 연구 단계에는 비상업 데이터도 허용, 파티션으로 분리

**결정** 비상업(NC)·동일조건(SA)·허가 필요 데이터도 연구용으로 적재한다. 단, 모두 `restricted`
파티션에 넣는다. 배포 빌드에는 `open` 파티션만 들어간다.

**파생**
- 파티션은 사람이 판단하지 않는다. `kb/licenses.yaml` 정책 표를 보고 코드가 계산한다
  (`LicenseEntry.partition`).
- 라이선스를 모르면(null) `restricted`로 둔다. 상업 이용 가능이 확인될 때까지 배포하지 않는다.
- 엔진도 같은 원칙을 따른다. 비상업 가중치(ASL 등)는 `allowed_in: [research]`만 허용하고
  `msl registry check`가 이를 강제한다.

## D3 — 공개 범위: 코어 오픈소스, Apache-2.0

**결정** 코어를 오픈소스로 공개할 것을 전제로 개발한다. 라이선스는 **Apache-2.0**이다.

**근거** 11절 권고는 "MIT 또는 Apache-2.0"이었다. 둘 중 Apache-2.0을 고른 이유는 두 가지다.
- 소재·화학 산업 사용자에게 의미가 있는 명시적 특허 허락 조항이 있다.
- 핵심 의존 모델(ORB v3), 실험계획 도구(BayBE)와 같은 라이선스다.

MIT·BSD·LGPL(동적 import) 의존성과 함께 쓸 수 있다.

**파생**
- GPL 엔진은 코어에 import하지 않는다. 격리 워커에서만 쓴다(계획서 5.4절).
- 아직 외부에 공개한 적이 없으므로, 공개 전까지는 MIT로 바꿀 수 있다.

## D4 — 우선 조합 도메인: 광물·세라믹 → 수용액 → 합금

**결정** 2단계 MVP 데모와 검증 세트는 광물·세라믹 고상반응을 중심으로 만든다.
3단계는 수용액, 그다음 합금 순으로 넓힌다.

**파생**

  매칭하는 작업이 1단계의 핵심이다.
- 데모 레시피 1번은 `limestone-quartz`(석회석 + 석영)로 한다.

## D10 — 원소 레이어는 두 가지로 구성: 연구용 mendeleev, 배포용 퍼블릭 도메인 소스

**발견** `kb/sources.yaml`을 작성하면서 MVP 1순위인 mendeleev와 CIAAW가 모두 `license: unknown`으로
분류됐다. mendeleev는 코드는 MIT지만 수록값은 CRC·위키백과(BY-SA)·RSC 등 출처가 섞여 있다. CIAAW는
재사용 조건을 명시하지 않았다. 따라서 둘 다 `restricted` 파티션에 들어가고, 배포 빌드에 넣을 원소
데이터가 없어진다.

**결정**
- 연구용(`restricted`): mendeleev를 쓴다. 속성이 118원소 × 83열로 가장 풍부하다.
- 배포용(`open`): periodictable(퍼블릭 도메인), PubChem 주기율표(NLM 생성분, 퍼블릭 도메인),
  Wikidata(CC0)로 조립한다. 원자량은 이 소스들의 값을 쓰고, CIAAW 조건이 확인되면 교체한다.
- 두 구성의 같은 속성 값을 1단계에서 비교해 차이를 기록한다.

**파생**
- `tests/test_registry.py::test_real_kb_open_element_layer_exists`가 배포용 원소 소스가 있는지 검사한다.
- 계획서 4.1절 E 레이어 설명을 이 구성에 맞게 고쳤다.

## D11 — 실행 가능한 최소 버전(v0)을 1단계보다 먼저 만든다 (2026-09-26)

**결정** 사용자가 실제 실행 화면을 먼저 보길 원해서, 계획 순서(1단계 데이터 대량 적재 → 2단계 시험)를
바꿔 **대량 적재 없이 계산되는 시험부터** 끝까지 연결했다. 레시피 → 해석 → 안전 게이트 → 라우터 →
시험 → 리포트(CLI·웹)까지 한 흐름이다.

**범위** S0·A1·A2·A3·A4·A7·A8·A10 실제 계산(A10 은 2026-09-27 data.go.kr 승인 후 연결). A5·A6·A9 는 이유와 함께 '대기'로 표시.

**이 과정에서 확인된 사실**
- MP DFT + Gibbs 근사는 방해석을 1,300 K 에서도 안정하다고 본다. NASA 실험 열화학(분해 약 900 °C)과
  어긋난다. 그래서 A2 에 **평형 트랙 교차검증**을 넣고, 불일치하면 결과를 '주의'로 낮춘다.
  계획서 3.3절의 두 축 설계가 필요한 이유를 실제로 확인한 사례다.
- 화학종을 약분 조성으로 찾으면 O₂ 가 산소 원자로 연결돼 단열 화염온도가 6,322 K 로 나왔다.
  정확한 조성 비교로 고치고 회귀 테스트를 넣었다(`tests/test_engines.py`).
- PubChem 은 `requests` 요청에는 503 을, 표준 `urllib` 요청에는 정상 응답을 준다. 원인은 확인하지
  못했고, PubChem 클라이언트는 `urllib` 을 쓴다.
- MP 요약 물성의 구조 일부는 r²SCAN 재계산분이라 밀도가 실측보다 약 3% 높다(Cu 9.22 vs 8.96).

**파생**
- 1단계(데이터 적재)는 그대로 다음 순서다. v0 의 PubChem 이름 조회는 IMA 매칭(1단계)으로 대체한다.
- S0 규칙은 자체 규칙 v0(7개)이다. NOAA 판정표를 확보하면 교체한다.

## D12 — 1단계 적재 방식 (2026-09-27)

**결정**
- **COD** 는 CIF 전량 미러 대신 광물명이 있는 항목의 메타데이터를 OPTIMADE 로 받는다(16,193건). CIF 전량은
  구조 계산이 필요한 단계에서 필요한 ID 만 받는다.
- **국내 규제 API**(한국환경공단·KOSHA)는 대량 적재하지 않고 조회할 때 캐시한다. 검색어가 필수이고 일일 호출
  한도가 있기 때문이다.
- **MP 요약 물성**(`phases_calc`, GGA/GGA+U/r²SCAN 혼합)은 조회·물성용이다. 안정성·반응 판정(A1·A2)은 계속
  GGA/GGA+U 엔트리로만 한다. 기준이 다른 에너지를 한 hull 에 섞지 않는다(계획서 3.5절).
- **한글 이름 해석**은 KOSHA 국문명이 **정확히 일치할 때만** 채택한다. 부분 일치는 오해석 위험이 크다.
- **ScienceBase(USGS MCS)** 는 Cloudflare 봇 검사가 있다. 새 판은 사용자가 브라우저로 받아 `data/raw/usgs-mcs/` 에
  둔다. 자동화로 봇 검사를 넘지 않는다.

**파생** 1단계 완료 기준 중 '4.4절 목표 적재'는 부분 충족으로 기록한다([05 적재 보고](05-1단계-데이터-코어.md)).

## D13 — A2 고온 반응은 '앵커' 하이브리드 열역학으로 판정한다 (2026-09-27)

**결정** 유한온도 A2 는 NASA 실험 ΔGf(T)가 있는 상은 그 값을 쓴다. MP 에만 있는 상은 NASA 에도 있는 상(앵커)으로부터의
반응에너지만 MP 에서 가져온다(고체끼리 반응이면 0 K DFT, 기체가 끼면 SISSO 온도 보정).

**근거** 삼원 산화물 11종 벤치마크의 반응에너지 MAE 가 원시 혼합 94, SISSO 앵커 29, 0 K 앵커 11 meV/atom 이다
([06 2단계 보고](06-2단계-조합-시험.md)). MP 값을 NASA 좌표계에 그대로 섞으면 MP 상이 수백 meV/atom 과안정화된다.

**파생**
- 계획서 3.5절의 '에너지 기준 혼용 금지'의 예외다. 대신 결과에 `energy_reference` 로 혼합 사실을, `sources_by_phase` 로
  상별 출처를 반드시 남긴다.
- 0 K DFT 곡선은 비교용으로 계속 보여 준다.

## D14 — A6 합금은 모든 원소 쌍이 평가된 TDB 에서만 계산한다 (2026-09-27)

**결정**
- 레시피 원소의 모든 2원계 쌍이 평가된 TDB 만 쓴다. 평가되지 않은 쌍은 이상용액으로 채우지 않는다.
- 적재한 SGTE 2원계 모음·COST 507 은 라이선스 미확인이라 연구용(restricted)이다. 배포 빌드에서 A6 은 동작하지 않는다.

**근거** 평가되지 않은 쌍을 이상용액으로 채우면 그럴듯한 오답이 나온다(예: LibreCalphad Cu–Ni 에서 FCC_L12 가 2,100 K 까지
잔존). 라이선스는 D2 원칙에 따라 확인 전까지 보수적으로 둔다.

**파생** SGTE 부록(Calphad 89 (2025) 102833)의 CC BY 적용 여부 확인이 선행 확인 목록에 추가된다.

## D15 — A5 Pourbaix 는 실험값 우선 하이브리드로, 실재하는 상만으로 그린다 (2026-09-27)

**결정**
- 고체: NASA 298.15 K ΔGf → 이온 데이터의 기준 고체 ΔGf(NBS) → 둘 다 없으면 MP 상을 실험 앵커에 잇는다(D13 과 같은 식).
- 이온: MPContribs ion_ref_data 의 실험 ΔGf 를 그대로 쓴다. 기준 고체가 실험값이면 Persson 2012 의 고체 보정 항이 0 이 된다.
- MP 에만 있는 고체는 실험 관측 구조(ICSD, MP `theoretical=false`)가 있는 것만 둔다.
- 이온 데이터는 mp-api 의 MPContribs 클라이언트 대신 공개 REST 스냅샷(CC BY 4.0)으로 받는다.

**근거**
- MP 원본 에너지(mp-api 기본)는 금속 11종의 면역 상한 전위 MAE 159 mV(최대 515 mV, Pb)였고, 하이브리드는 9 mV(최대 38 mV).
- MP 원본은 금이 공기 중 물에서 녹는다(H₃AuO₃)고 보고, 수산화물을 크게 불안정하게 다뤄 Mg(OH)₂ 부동태를 놓친다.
  A5 검증 사례 11개 중 MP 원본 9개, 하이브리드 11개 통과.
- 앵커만으로는 GGA 가 과안정화한 가상 상(Cu₂O₃)이 산소 선 아래에 남았다. 관측 상만 두자 Cu 는 Cu·Cu₂O·CuO,
  Fe 는 Fe·Fe₃O₄·Fe₂O₃·Fe(OH)₂ 로 Pourbaix 도감과 같은 구성이 됐다.
- MPContribs 클라이언트(mp-api[contribs])는 pint>=0.25 를 요구해 mendeleev(pint<0.25)와 설치가 충돌한다.

**파생** 결과마다 상별 에너지 출처(NASA / 실험 기준 고체 / MP-앵커)를 남기고, MP 에 기댄 상이 판정에 쓰이면 경고한다.

## D16 — 조합 공간 생성기는 레시피를 만드는 계층으로 둔다 (2026-09-27)

**결정**
- 공간 정의(`examples/spaces/*.yaml`)는 레시피 틀(base) + 생성기 + 수집 열(collect)로 이뤄진다.
- 생성기는 세 가지다: ratio(혼합비 단체 격자), amount(한 성분의 양), subsets(풀에서 k개 조합, 원소계 탐색 포함).
- 생성된 레시피는 보통 레시피와 똑같이 `run_recipe` 로 돈다. 시험 코드는 공간을 모르고, 결과 캐시도 그대로 재사용한다.
- 결과는 표(CSV·Markdown), 1차원이면 곡선, 두 개씩 조합이면 쌍별 행렬로 보여 준다.

**근거** 시험마다 스윕을 따로 구현하면(A6 의 T 스윕, A2 의 혼합비 곡선) 조합 방식이 시험 수만큼 늘어난다.
레시피 계층에서 만들면 새 시험도 자동으로 공간 탐색이 된다. 공간 탐색은 기존 시험의 버그도 드러냈다

**파생** 4단계 '다음에 시험할 조합 추천(BayBE)'은 이 공간 정의를 탐색 대상으로 쓴다.

## D17 — L1 조성 대리모델은 자체 특성 + 그래디언트 부스팅으로, 신뢰도 정보와 함께 낸다 (2026-09-27)

**결정**

## D20 — L2 후보 구조는 Ewald 순위 배치 + 다른 화학계 구조 원형으로 만든다 (2026-09-27)

## D21 — L2 물성(탄성·포논)과 L2 → L3 승격 규칙 (2026-09-27)

**결정**
- 탄성: uMLIP 으로 6방향 ±0.5·±1% 변형 → 원자만 이완 → 응력 기울기로 탄성 텐서, 체적·전단 탄성률(VRH). matcalc 는
  phono3py 등 의존성이 무거워 쓰지 않고 pymatgen 으로 직접 계산한다.
- 포논: phonopy (BSD-3, l2 묶음), 한 변 ≥ 10 Å 초격자, 힘 상수 대칭화(음향 합 규칙). 최소 진동수 < −0.3 THz 면 동역학적 불안정.
  포논은 float64 인 MACE 로 계산한다 (ORB float32 는 NaCl 에서 −0.44 THz 잡음).
- L3 승격: 새 조성의 L2 hull 거리 ≤ 0.05 → '권장', 0.05~0.1 → '선택', 그 밖은 '불필요'. 두 모델 차이 > 0.03 이면 불확실 표시,
  포논 허수 모드면 DFT 재이완 필요 이유를 붙인다. DB 에 있는 조성은 '불필요'.

**검증** (`msl bench props`, MP DFT 탄성 데이터 대비)

| 모델 | 체적탄성률 MAE | 전단 MAE | 포논 판정 |
|---|---|---|---|
| MACE-MPA-0 | 6.6 GPa (6%) | 약 10 GPa | 7/8 |
| ORB v3 | 5.3 GPa (4%) | 약 10 GPa | 6/8 (NaCl float32 잡음) |

- 입방정 BaTiO₃(0 K 불안정)는 두 모델 모두 허수 모드로 맞혔다.
- 루틸 TiO₂ 는 두 모델 모두 허수 모드 — GGA 계산에서 루틸이 0 K 불안정으로 나오는 알려진 현상(Montanari & Harrison 2002)과 같아
  모델 오류로 보지 않는다. MP 의 Al 전단 탄성률은 −14 GPa 로 잘못 들어 있어 비교에서 뺐다.
- Li₆MnNi₃O₁₀ 의 L2 최저 구조(C2/m)는 포논 안정 → L3 승격 '권장' (hull +0.040).

## D22 — Reaktoro 는 A4 교차검증으로만, 고온 DB 는 보류 (2026-09-27)

**결정**

## D26 — L2 후보 구조: 과산화물 모체 제외, 원형은 서로 다른 구조형으로 (2026-09-27)

**배경** — D24 평가에서 Li₂SiO₃(안정)를 불안정으로 판정했다. 후보 구조를 보니
(1) 원형 4개가 모두 같은 층상 구조형(Li₂RuO₃·Li₂NiO₃ ×2·Li₂TcO₃)이었고 실제 사슬 구조형(Na₂SiO₃·Li₂GeO₃ 형, Cmc2₁)이 없었다.
이온 반지름 차이만으로 순위를 매겨 한 구조형으로 몰렸다. (2) 모체에 과산화물 Li₂O₂ 가 들어 있었다 — MP 의 oxide_type 이
비어 있거나 'oxide' 로 잘못 적힌 엔트리를 그대로 통과시켰다.

**결정**
- 원형 배정 비용 = 산화수별 이온 반지름(Shannon)의 상대 차이 + 형식 전하 차이의 절반. 전하가 2 이상 다른 배정은 버린다.
- 같은 구조형(원소까지 같게 장식했을 때 StructureMatcher 로 일치)은 하나만 남겨, 서로 다른 구조형을 6개까지 고른다 (전에는 4개).
- 산화물 모체는 양이온의 최대 산화수 합으로 O²⁻ 를 맞출 수 있어야 한다 (Li₂O₂·Li₃SiO₄ 제외).

**결과** (`msl bench l2-f1`, 같은 30개 세트)

| | D24 (수정 전) | D26 |
|---|---|---|
| 주 기준 F1 | 0.903 | **0.882** |
| 재현율 | 0.93 | **1.00** |
| 정밀도 | 0.88 | 0.79 |
| 평균 절대 오차 | 0.029 | 0.026 eV/atom |
| 재발견 시험 (D20) | 7/7 | 7/7 |

- Li₂SiO₃: 원형 Li₂GeO₃ 로 실제 구조를 찾아 −0.037 (정답 −0.037). 미탐이 없어졌다.
- 새 오판 2개: Li₂MnO₂ (정답 +0.010) 는 MP 구조를 줘도 −0.002 — 구조 탐색이 아니라 경계에서의 uMLIP 에너지 오차이고,
  전에는 구조를 못 찾아 우연히 맞았다. Ca₂TiO₄ (정답 +0.036) 는 원형 Ca₂GeO₄ 로 MP 구조보다 0.08 낮은 구조를 찾았다 —
  uMLIP 착시인지 MP 에 없는 더 안정한 구조인지는 DFT 로만 가린다 (L3 후보).
- F1 은 조금 내려갔지만 유지한다. L2 는 DFT(L3)로 넘기는 거르기 단계라 오판은 다음 단계에서 걸러지지만 미탐은 되살릴 수 없다.
  구조 탐색이 좋아질수록 uMLIP 에너지 오차가 오판으로 드러나는 것은 예상된 대가다.
- Li₆MnNi₃O₁₀ 은 원형이 없고 모체(LiNiO₂·LiMnO₂·MnO)가 그대로라 D24 결과(+0.040) 가 유지된다.
- 이전 결과는 `kb/validation/l2_f1_v2.json` (D24), 재발견은 `l2_rediscovery_v3.json`.

## D27 — A4: phreeqc.dat 이 모르는 산화 상태는 llnl.dat 으로, 락스 + 산은 염소 기체 분압까지 (2026-09-27)

**배경** — 웹 사용 점검에서 가장 흔한 위험 조합인 락스(차아염소산나트륨)가 A4 에서 '계산하지 않음'으로 나왔다.
phreeqc.dat 에는 염소가 Cl⁻ 하나뿐이다. S0 는 규칙으로 "염소 기체 발생"을 알리지만 얼마나 나오는지는 계산하지 못했다.

**결정**
- A4 는 phreeqc.dat 으로 먼저 계산하고, 그 DB 에 없는 산화 상태가 있으면 전체를 llnl.dat 으로 계산한다.
  llnl.dat (LLNL thermo.com.V8.R6, PHREEQC 배포본 동봉)은 Cl(+1)=ClO⁻ ~ Cl(+7) 과 Cl₂(g) 상이 있다. USGS 공공 배포 조건이라
  패키지(`src/msl/data/phreeqc/`)에 수정 없이 넣고 NOTICE 에 적는다. 활동도 모델은 B-dot, 0–300 °C.
- 산화수 배정은 pymatgen 기본 추정이 DB 에 있으면 그대로, 아니면 DB 가 아는 산화 상태 안에서 다시 찾는다
  (pymatgen 은 Cl⁺¹ 을 흔한 상태로 보지 않아 NaClO 추정이 비었다).
- 산화 상태는 섞은 그대로 둔다. 차아염소산은 열역학적으로 염화물 + 산소로 분해되지만 느린 반응이라 완전한 산화환원 평형을 풀면
  락스가 사라지는 잘못된 답이 나온다. 대신 빠른 반응인 HOCl + H⁺ + Cl⁻ ⇌ Cl₂(g) + H₂O 만 평형으로 보고,
  PHREEQC 가 계산한 활동도로 염소 기체 평형 분압을 구한다:
  log P(Cl₂) = log a(ClO⁻) + log a(Cl⁻) + 2 log a(H⁺) − k₁(ClO⁻) − K₂(Cl₂(g)), 상수는 llnl.dat 의 온도식 그대로 읽는다.
  (llnl 에는 수용액 Cl₂ 가 없고, Cl(+1)/Cl(−1) 짝으로 pe 를 정하는 PHREEQC 초기 용액은 수렴하지 않았다.)
- llnl 로 계산한 결과는 Reaktoro 교차검증을 하지 않는다 — Reaktoro 는 산화 상태까지 모두 평형으로 풀어 비교가 맞지 않는다.

**검증**

| 조합 (물 1 L, 25 °C) | pH | 염소 평형 분압 | 기준 |
|---|---|---|---|
| 락스 0.05 M | 10.05 | — | pKa(HOCl) 7.5 → 약 10 |
| 락스 0.05 + 염산 0.1 M | 1.39 | **5.4 atm** (기체 발생) | K = 10^4.53 (문헌 10^4.55) 손계산 5.3 atm |
| 락스 0.05 + 염산 0.01 M | 8.08 | 2×10⁻⁸ atm | 약염기성이면 거의 없음 |
| 락스 0.05 + 소금 0.1 M | 10.01 | 3×10⁻¹¹ atm | 염기성에서는 사실상 없음 |

- 검증 세트에 a4-bleach, a4-bleach-hcl-chlorine 두 사례를 더했다.
- 과망간산(Mn⁺⁷)·철산염(Fe⁺⁶) 등은 두 DB 모두 없어 여전히 '계산하지 않음' — 이유를 쉬운 말로 알린다.
- 한계: 빠져나가는 기체로 농도가 줄어드는 과정, 물 활동도(1 로 둠), 고농도(대략 1 mol/kg 이상)는 반영하지 않는다.

## D28 — uMLIP 에너지 보정은 하지 않는다 (시험 결과 효과 없음), 두 모델 일치 규칙은 새 세트로 확인 후 (2026-09-28)

**시험한 것** — 이미 이완해 둔 경쟁 상(18개 산화물 화학계, 3원계 이상 260개)으로 'uMLIP 분해 에너지 − MP 분해 에너지' 잔차를 보고,
전이금속 산화수별 에너지 보정을 두 방식으로 맞췄다 (스크립트 `kb/validation/scripts/umlip_oxidation_correction.py`).
원소별 일정값 보정은 분해 에너지에서 상쇄되므로 처음부터 제외했다.

| 방식 | 평균 절대 오차 (eV/atom) | 부호가 틀린 조성 |
|---|---|---|
| 보정 없음 | 0.0077 | 22 |
| 전체 화학계로 맞춤 (자기 화학계 제외, LOCO) | 0.0077 | — |
| 같은 화학계의 알려진 경쟁 상으로 맞춤 (대상 제외) | 0.0076 | 25 |

**결정 — 보정하지 않는다.**
- 경쟁 상 기준을 같게 맞추면 3원계 분해 에너지 오차는 이미 0.008 eV/atom 로 DFT 자체 오차보다 작다.
- 큰 오차(ZnFe₂O₄ −0.067, Li–Co–O 계 −0.02~−0.06)는 산화수로 설명되지 않는다 — ZnFe₂O₄ 와 분해 생성물 Fe₂O₃ 는 둘 다 Fe³⁺ 라
  산화수별 보정이 상쇄된다. 자성 배열·구조에 따른 오차로 보이며 조성 기반 보정으로는 줄지 않는다.
- Co 화학계가 하나뿐이라 화학계를 빼고 맞추면 Co 보정을 배울 데이터도 없다.

**F1 오판의 실제 원인** (D26 세트, 오판 4개): Li₂CoO₂·LiFe₂O₃ 는 두 모델의 부호가 엇갈렸다 (ORB 가 맞음, MACE 가 틀림).
Li₂MnO₂ 는 hull 위 0.010 경계, Ca₂TiO₄ 는 두 모델 모두 MP 보다 0.08 낮은 구조를 찾았다 (DFT 확인 후보).

**사후 분석 (적용하지 않음)** — 같은 30개에서 '두 모델 모두 ≤ 0 일 때만 안정'으로 판정하면 F1 0.882 → 0.938
(정밀 0.79 → 0.88, 재현 1.00 유지). 결과를 보고 고른 규칙이라 같은 세트로 성능을 주장할 수 없다.
다른 화학계로 새 평가 세트를 만들어 확인한 뒤에만 제품 규칙으로 바꾼다.
