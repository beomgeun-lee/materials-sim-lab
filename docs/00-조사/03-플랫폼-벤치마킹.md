# 03. 통합 플랫폼·제품·워크플로 벤치마킹

- 작성일: 2026-09-26 (모든 사실은 이 날짜 기준 웹 확인)
- 범위: 통합 플랫폼, 상용 스위트, 워크플로·프로비넌스 프레임워크, 교육용 가상실험실, LLM 에이전트, 자율실험실(SDL) 소프트웨어, 데이터 표준. 개별 데이터 소스 목록과 개별 계산 엔진 평가는 다른 조사 문서에서 다룬다.
- 방법: 공식 문서·보도자료·논문(arXiv)·PyPI 메타데이터(최신 버전·배포일·라이선스)로 확인했다. 확인하지 못한 항목은 "미확인"으로 표시했다. 가격은 공개된 것만 적었다.

## 0. 요약

### 0.1 핵심 결론

1. **'조합 → 여러 시험'을 한 흐름으로 묶은 제품은 이번 조사 범위에서 찾지 못했다.** 도구는 도메인별로 나뉘어 있다. 무기결정은 MP·AFLOW·OQMD·JARVIS, 분자는 PubChem·RDKit·MPcules, 수계·지구화학은 PHREEQC·Reaktoro·OLI, 합금·고온은 Thermo-Calc·FactSage, 혼합위험은 CAMEO, 소재 선정은 Granta·MatWeb이 맡는다. 도메인마다 입력 표현(결정구조, SMILES, 용존종, 몰분율, CAS)이 달라서 서로 이어 주는 계층이 없다.
2. **가장 가까운 것은 Materials Project다.** 결정 DFT, Pourbaix, 반응 계산기, 계면 반응(Interface Reactions), 분자 17만 건, 합성 레시피를 갖췄고 공식 MCP도 제공한다. 하지만 0 K DFT 중심이다. 앱끼리 연결되지 않고, 사용자가 시험 흐름을 직접 정의할 수 없으며, 합금 CALPHAD·수용액 종분화·안전 판정도 없다.
3. **'성분 조합 → 평형' 범위가 가장 넓은 것은 열화학 상용 3종(HSC·FactSage·Thermo-Calc)이다.** 다만 모두 데스크톱 제품이고 DB가 폐쇄적이며, 원자 수준 계산·ML·프로비넌스·웹 UI가 없다. 경계는 넓어지는 중이다. Thermo-Calc 2026a는 수용액 DB(TCAQ4)와 Pourbaix 계산기를 추가했다.
4. **2026년에는 '범용 MLIP + LLM 에이전트' 조합이 상용 단계에 들어섰다.** Matlantis는 2026-05에 Claude Code를 내장했고, Microsoft Discovery는 2026-06에 정식 출시(GA)됐다. Materials Studio·Schrödinger·QuantumATK도 모두 MLIP를 탑재했다. 대형 투자(CuspAI $450M, Periodic Labs $300M)도 폐쇄형 기업용이다. 오픈·로컬·공공데이터·교육 영역은 비어 있다.
5. **기반 부품은 이미 충분히 성숙했다.** 워크플로는 AiiDA 2.9.2, jobflow-remote 1.0.1, pyiron, quacc와 교환 포맷 PWD가 있다. 표준은 OPTIMADE v1.3, XTDB, ThermoML이 있다. 에이전트 접점은 MP MCP(mp_api 내장), OPTIMADE MCP, ChemMCP가 있다. 따라서 엔진을 새로 만들기보다 **'공통 조합 레시피 스키마 + 도메인 라우터 + 프로비넌스 + 안전 게이트'**를 차별화 지점으로 삼아야 한다.
6. **에이전트 시대의 가장 큰 공백은 안전이다.** ChemMat-AgentSafetyBench(2026-07)에서 화학·소재 에이전트는 실행의 25.6%에서 위험한 합성·제조 절차를 완전히 노출했다. CAMEO식 반응성 그룹 매트릭스를 시험 전 게이트로 내장해야 한다.
7. **포지셔닝 권고:** 코어는 '연구자용 오픈소스 SDK + MCP'(1안)로 하고, 그 위에 첫 사용자 접점으로 '교육용 가상 조합 실험실'(2안)을 얹는다. 산업용 스크리닝(3안)은 앞의 두 안을 검증한 뒤 진행한다.

## 1. 카테고리별 상세

평가 항목: 무엇 / 핵심 기능 / 대상 / 가격·라이선스 / 아키텍처 / 강점 / 약점·빈틈 / **차용점**

### A. 오픈 소재 데이터+분석 웹 플랫폼

#### A1. Materials Project (LBNL, DOE)
- **무엇**: 고처리량 DFT로 만든 무기소재 DB와 분석 웹앱.
- **현재 앱 목록(2026-09 문서 기준)**
  - 탐색: Materials, Molecules, Battery, Synthesis, Catalysis, MOF, Reverse Pourbaix Explorer
  - 분석: Phase Diagram(1~4원계, 2~3원계 화학퍼텐셜도), Pourbaix, Crystal Toolkit, Reaction Calculator, Interface Reactions
  - 특성화: XAS
  - 서비스: MPContribs(사용자 기여 데이터), ML&AI(MatBench, Matbench Discovery, MPtrj, r2SCAN 데이터셋, **MP + LLMs(MCP)**), API, Data Lakehouse
- **최신 DB**: v2026.04.13, 2026-06-08 공개
  - 코어 데이터를 S3 Delta 테이블로 전환
  - GNoME r2SCAN 물질 74,052건 추가(누계 117k)
  - r2SCAN 전면 재계산 진행 중(비GNoME 약 26%)
  - 포논 데이터 +26k
  - 알파벳 ID 체계(하위 호환 유지)
- **분자**: MPcules 17만+(이온 98,480, 중성 74,394). 원래 전해질(JCESR) 중심이며 CC BY 4.0.
- **합성**: Synthesis Explorer는 논문 53,538개 문단에서 텍스트마이닝한 19,488건의 고상 합성 레시피(전구체·조작·조건·균형 반응식)를 담고 있다.
- **대상**: 연구자, 학생, ML 연구자
- **가격·라이선스**: 무료(API 키 필요). mp-api 0.46.5(2026-08-18), BSD-3-Clause-LBNL. pymatgen 2026.9.24(MIT), emmet-core, crystal-toolkit 모두 PyPI로 공개돼 있다.
- **아키텍처**: atomate2/jobflow 계산 → emmet 빌더 → 데이터 레이크하우스(Delta, Arrow) → mp-api 클라이언트 → 웹(Crystal Toolkit 컴포넌트). MCP는 mp_api 0.46.0 이상에 내장돼 있다(fastmcp 기반 `search`·`fetch` 2개 도구. `fetch_all`·상태도 도구는 "예정"으로 표기).
- **강점**: 데이터 규모와 신뢰도. 앱마다 과학적 방법이 명확하다(convex hull, grand potential, Pourbaix). 에이전트 접점을 공식 지원한다.
- **약점·빈틈**
  - 0 K DFT 에너지가 중심이라 온도·압력·용액 활동도 반영이 제한적이다.
  - 앱이 서로 독립적이다. "A와 B를 섞으면?"에 여러 시험을 한 번에 돌리는 흐름이 없다.
  - Interface Reactions는 2성분까지만 다룬다.
  - 합금 고용체 CALPHAD, 유기 반응, 혼합위험은 다루지 않는다.
- **차용점**
  1. Interface Reactions의 "혼합비 스윕 → 반응에너지 곡선 + 생성물 목록" UX(pymatgen `InterfacialReactivity`, 열린 원소 저장소를 두면 grand potential 상태도)
  2. Pourbaix의 "DFT 고체 에너지 + 실험 이온 에너지" 결합 방식 → 도메인 간 에너지 기준을 맞추는 보정 계층의 원형
  3. MCP의 2-도구(search/fetch) 최소 설계
  4. Crystal Toolkit 웹 컴포넌트
  5. Delta/Arrow 벌크 배포 방식

#### A2. AFLOW (Duke 중심)

- 상용 DB는 재배포가 불가능할 가능성이 높으므로 링크하거나 사용자가 보유한 데이터를 가져오는 방식으로 처리한다.

## 2. 2026 시점 동향 요약

- **데이터 규모와 인프라 전환**: MP가 Delta Lake/S3로 전환하고 GNoME r2SCAN을 대량 편입했다. OPTIMADE는 2,000만 건 이상을 연합 검색한다. 한 로드맵 논문(arXiv 2609.19833, 2026-09-17)은 "구조·에너지·탄성·위상은 일상 생산 단계에 있지만 NMR·코어준위 스펙트럼·전자-포논·열전도·양자 수송 등 9개 물성군은 체계적 DB가 없다"고 정리한다.
- **범용 MLIP가 사실상 표준**: MACE(Materials Studio), MPNICE·UMA(Schrödinger), MTP(QuantumATK), PFP(Matlantis), Orb(공개). "MLIP로 스크리닝 → DFT로 확인"하는 충실도 사다리가 상용·오픈 모두에 정착했다.
- **에이전트화**: 상용은 Matlantis+Claude Code와 Microsoft Discovery GA, 연구는 에이전트 약 50종이 나왔다. MCP가 도구 연결 표준으로 자리 잡는 중이다(MP 공식 MCP).
- **안전·신뢰가 병목**: 에이전트 안전 벤치마크가 높은 위험 노출률을 보고했다. 폐루프 SDL 쪽은 감사 가능성(auditability)을 설계 요건으로 명시하고 있다(La Agente Óptima).
- **자본 집중**: CuspAI $450M, Periodic Labs $300M, Orbital $50M. 모두 폐쇄형이고 기업·파트너십 중심이다.

### 3.3 판정
- **"하나의 조합 레시피 → 도메인 자동 판별 → 여러 종류의 시험 → 통합 보고"를 제공하는 제품은 확인하지 못했다.** 검색 범위 밖에 사내 도구나 신생 서비스가 있을 가능성은 배제할 수 없다.
- 구체적 빈틈 6가지:
  1. **공통 "조합 레시피" 스키마 부재**: 원소, 광물, 분자, 용액, 상용 합금 등급을 한 목록에 비율·상태·조건과 함께 담는 표준이 없다. FactSage Mixture와 Citrine GEMD가 부분 선례다.
  2. **도메인 자동 라우팅 부재**: "이 조합에 유효한 시험"을 판정하는 기능이 없다. 예: 고체-고체면 hull·계면 반응, 수용액이면 종분화·Pourbaix, 금속이면 CALPHAD, 유기면 RDKit·반경험.
  3. **안전이 시뮬레이션 흐름 밖에 있다**: CAMEO는 별도 사이트이고 에이전트 안전 방어도 미흡하다.
  4. **충실도·불확실성 표기가 제각각이다**: 0 K DFT, 298 K 실험, ML 예측 결과를 같은 화면에서 비교할 규칙이 없다. JARVIS Leaderboard와 Citrine 불확실성이 부분 선례다.
  5. **교육 UX와 실제 과학 엔진이 떨어져 있다**: ChemCollective·PhET은 고정 모델, 전문 도구는 초보자 접근이 불가능하다.
  6. **가상 시험과 실제 실험이 단절돼 있다**: BayBE·MADSci는 실험 쪽, MP·CALPHAD는 계산 쪽이다. 둘을 같은 레시피 ID로 잇는 오픈 도구는 확인하지 못했다.
- **경쟁 위협**: Microsoft Discovery, Matlantis, CuspAI 같은 범용 에이전트 플랫폼이 도구를 붙여 빈틈 1·2를 부분적으로 메울 수 있다. 차별화 축은 **오픈, 로컬 자체 호스팅, 공공데이터, 안전 게이트, 교육**이다.
